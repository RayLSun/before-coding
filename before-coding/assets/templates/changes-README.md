# Change Agreements

Use this directory for new features, cross-module changes, and work with meaningful design trade-offs. Small fixes can use a short agreement in the active conversation.

Each agreement should state:

- Goal and user-visible outcome
- In-scope and out-of-scope behavior
- Existing behavior that must remain unchanged
- Acceptance criteria and regression checks
- Decisions requiring user input
- Verification result and product-baseline updates after implementation

Do not create a full spec, architecture document, implementation plan, review report, and test report for every small change. Keep one focused record when it will help future work.
